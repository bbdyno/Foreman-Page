01시작하기

Foreman은 두 부분으로 나뉩니다. 에이전트가 실제로 도는 컴퓨터에는 호스트를, 세션을 보고 승인할 기기에는 앱을 설치합니다. 호스트는 세션을 직접 소유하므로 터미널 창을 닫거나 연결이 끊겨도 에이전트는 계속 돌고, 앱은 언제든 다시 붙습니다.

Mac 호스트 설치

  1. Foreman Host를 응용 프로그램 폴더에 두고 엽니다. Dock에는 나타나지 않고 메뉴 막대에 펄스 아이콘이 생깁니다.
  2. 메뉴를 열어 맨 위에 “이 Mac이 호스트로 동작 중”이 보이면 준비가 끝난 것입니다. 그 아래 줄에 foremand 버전과 세션 수가 나옵니다.
  3. 메뉴의 로그인 시 시작을 켭니다. 이제 Mac에 로그인할 때마다 호스트가 자동으로 뜨고, 꺼지면 몇 초 안에 다시 뜹니다. 토글 옆에 “승인 필요”가 보이면 시스템 설정 › 일반 › 로그인 항목에서 Foreman Host를 허용합니다.
  4. 같은 Mac에서 Foreman 앱을 쓰면 페어링 없이 바로 이 호스트에 연결됩니다.

Foreman 앱을 엽니다.

Foreman Host 앱만 끝냅니다. 호스트 데몬과 세션은 계속 돕니다.

Windows 호스트 설치

  1. Foreman Host 패키지(MSIX)를 설치합니다. Windows 10 버전 1809 이상이 필요합니다.
  2. 설치하면 foreman 명령, 호스트 데몬, 개인·도메인 네트워크용 방화벽 규칙이 함께 들어옵니다. 따로 설정할 것은 없습니다.
  3. 로그온할 때 호스트가 자동으로 시작되도록 시작 작업 “Foreman Host”가 등록됩니다. PowerShell에서 foreman autostart status로 상태를 확인합니다. 꺼져 있다고 나오면 작업 관리자 › 시작 앱에서 Foreman Host를 켭니다.
  4. foreman doctor를 실행해 이 PC가 계속 켜져 있을 준비가 됐는지 확인합니다(항상 켜 두기).

패키지 없이 압축 파일로 받은 호스트는 foreman autostart enable 한 번으로 로그온 시 시작을 켭니다. 관리자 권한은 필요 없습니다.

앱 설치

iPhone과 iPad는 App Store에서 Foreman을 받습니다. Apple Watch 앱은 iPhone 앱과 함께 설치됩니다. Mac에서 세션을 보려면 Foreman 앱을, 그 Mac을 호스트로 쓰려면 Foreman Host를 설치합니다. 둘은 별개의 앱이고 한 Mac에 같이 둘 수 있습니다.

02페어링

앱은 페어링한 호스트에만 연결합니다. 페어링할 때 양쪽이 서로의 키를 확인하고, 그 뒤의 모든 연결은 처음부터 끝까지 암호화됩니다.

QR 코드로 연결

  1. 호스트 Mac의 메뉴 막대에서 Foreman Host › 다른 기기와 페어링…을 엽니다. Windows 호스트에서는 PowerShell에서 foreman pair를 실행합니다. 터미널에 QR 코드가 나옵니다.
  2. iPhone이나 iPad의 Foreman에서 설정 › 호스트 페어링…을 열고 QR 코드를 비춥니다. 카메라가 없는 기기와 Mac 앱에서는 호스트에 표시된 링크(foreman://pair?…)를 “또는 페어링 링크” 칸에 붙여 넣고 연결을 누릅니다.
  3. 코드는 한 번만 쓸 수 있고 5분 뒤 만료됩니다. 만료됐다면 호스트에서 새 코드를 누릅니다.

6자리 확인 코드

연결이 열리면 호스트와 기기에 같은 여섯 자리 숫자(예: 491 795)가 나옵니다. 이 숫자는 두 기기가 주고받은 암호 키에서 계산되므로, 중간에 누가 끼어들면 숫자가 달라집니다.

  1. 기기에 “호스트 화면의 숫자와 같나요?”, 호스트에 “…가 페어링을 요청해요. 기기 화면의 숫자와 같나요?”가 뜹니다.
  2. 두 숫자가 같으면 양쪽에서 같아요를 누릅니다. foreman pair에서는 y를 입력합니다.
  3. 양쪽이 모두 확인해야 페어링이 끝납니다. 기기에 “…와 페어링했어요”가 나오면 완료입니다. 이후에는 호스트가 켜져 있는 한 앱을 열 때마다 자동으로 연결됩니다.

숫자가 다르면 달라요를 누르세요. 페어링하지 않고 끝납니다. 누군가 연결 중간에 끼어든 경우일 수 있으니, 새 코드로 다시 시작하기 전에 네트워크를 확인하세요.

여러 호스트와 연결 상태

한 앱에 호스트를 여러 대 페어링할 수 있습니다. 호스트마다 위의 과정을 한 번씩 거칩니다. 페어링한 호스트 수는 설정에 “페어링한 호스트 N대”로 나오고, 호스트 탭에서 각 호스트의 상태를 봅니다.

상태뜻
연결됨호스트와 연결되어 있습니다. 어떤 경로로 연결됐는지 함께 표시됩니다.
연결 중 · 다시 연결하는 중연결을 여는 중입니다. 연결이 끊기면 앱이 저절로 다시 시도하고, 끊긴 지점부터 출력을 이어 받습니다.
꺼짐 추정두 번 연달아 연결하지 못했습니다. 호스트가 꺼져 있거나 잠들어 있을 가능성이 높습니다. 호스트가 켜지면 자동으로 다시 연결합니다.
거절됨 · 다시 페어링 필요호스트에서 이 기기를 폐기했습니다. 다시 쓰려면 새로 페어링합니다.

호스트를 누르면 연결 경로, 켜진 지, 암호화 방식(Noise XX · 종단간)을 볼 수 있습니다.

기기 관리와 폐기

호스트 Mac의 Foreman Host › 기기 관리…에서 이 호스트에 페어링된 기기와 키 지문, 지금 연결됐는지를 봅니다. 잃어버린 기기나 더 쓰지 않는 기기는 폐기를 누릅니다. 페어링이 바로 해제되고 열려 있던 연결도 끊깁니다. Windows 호스트에서는 foreman devices로 목록을 보고 foreman devices revoke <id>로 폐기합니다.

앱에서 호스트 지우기

iPhone·iPad에서 호스트를 열고 이 호스트와의 페어링 해제를 누르면 이 기기에 저장된 호스트 키가 지워집니다. 호스트 쪽의 기기 목록은 그대로이므로, 완전히 정리하려면 호스트의 기기 관리에서도 이 기기를 폐기하세요.

03에이전트 연결

지원하는 에이전트

에이전트Foreman이 따라가는 방식
Claude Code대화, 도구 사용, 승인 요청과 질문을 모두 앱에서 보고 답합니다. 터미널에서 시작했든 앱에서 시작했든 같습니다.
Codex앱에서 시작하면 대화와 승인을 모두 다룹니다. 터미널에서 시작하면 터미널 화면과 대화 기록을 따라갑니다.
Gemini CLI · OpenCode앱에서 시작한 세션의 대화와 승인을 다룹니다.
그 밖의 명령터미널 화면을 그대로 보고 입력합니다.

터미널에서 평소처럼 실행하기

셸 연동을 켜 두면 터미널에서 claude, codex, gemini, opencode를 평소처럼 실행해도 Foreman 세션으로 들어옵니다. 앱에서 바로 보이고, 터미널을 닫아도 세션은 호스트에서 계속 돕니다.

Mac (zsh)

/Applications/ForemanHost.app/Contents/MacOS/foreman shim install

~/.zshrc에 Foreman 표시가 붙은 블록이 추가되고, 원래 파일은 .foreman-backup-날짜로 백업됩니다. 새 터미널을 열면(또는 exec zsh) 적용됩니다.

Windows (PowerShell)

foreman shim install

PowerShell 프로필에 같은 블록이 추가됩니다. 새 PowerShell 창부터 적용됩니다. 실행 정책이 Restricted나 AllSigned라면 안내에 따라 Set-ExecutionPolicy -Scope CurrentUser RemoteSigned를 직접 실행하세요. Foreman이 정책을 바꾸지는 않습니다.

  • 한 번만 Foreman 없이 실행하려면 command claude(PowerShell에서는 claude.exe)처럼 실행합니다.
  • 특정 에이전트만 연동하려면 foreman shim install claude codex처럼 이름을 붙입니다.
  • 상태는 foreman shim status, 해제는 foreman shim uninstall로 합니다.

발견된 에이전트 연결

호스트를 열고 에이전트로 들어가면 연결된 에이전트와 계정, 사용 중인 한도가 보입니다. 호스트에 설치돼 있지만 아직 연결하지 않은 에이전트는 “발견됨”에 나오고, 연결을 눌러 추가합니다.

승인 없이 실행하는 에이전트

에이전트를 --dangerously-skip-permissions나 --permission-mode bypassPermissions로 실행하거나 Codex의 승인 정책을 never로 두면, 에이전트가 승인을 묻지 않고 바로 명령을 실행합니다. 이때 Foreman은 에이전트가 하는 일을 보여 줄 수는 있지만 멈출 수는 없습니다. 위험한 작업을 앱에서 막고 싶다면 이 옵션 없이 실행하세요.

Free에서 쓸 수 있는 에이전트

Free에서는 에이전트를 두 종류까지 연결합니다. 세 번째 종류를 터미널에서 실행하면 일반 터미널 세션으로 돌아가며, 대화와 승인은 다루지 않습니다. Pro에서는 제한이 없습니다(Pro).

04승인과 질문

에이전트가 명령을 실행해도 되는지 묻거나 질문하면, 모든 호스트의 요청이 앱의 승인 탭에 모입니다. 답을 기다리는 세션에는 ● 표지가 붙습니다.

승인 인박스

위쪽 필터로 전체, 승인, 질문을 나눠 봅니다. 요청마다 프로젝트, 에이전트, 호스트, 실행하려는 명령이 나오고 거부와 허용 버튼이 있습니다. 홈이나 목록에서는 요청을 밀어서도 허용하거나 거부할 수 있습니다.

Face ID로 허용

위험한 요청에는 Face ID로 허용 버튼이 나옵니다(Mac은 Touch ID). 본인 확인이 끝나야 허용이 호스트로 갑니다. 확인을 취소하면 “허용하지 않았어요”가 뜨고 요청은 그대로 남습니다. 기기에 암호가 설정돼 있지 않으면 위험한 요청을 허용할 수 없으니, 기기 설정에서 암호를 켜 두세요.

잠금화면과 Live Activity

알림을 길게 누르면 앱을 열지 않고 답할 수 있습니다.

위험 높음 · 승인 필요거부, 세션 열기 — 허용은 앱 안에서 Face ID로

세션이 도는 동안에는 잠금화면과 Dynamic Island에 Live Activity가 떠서 실행 중인 세션 수와 당신 차례 수를 보여 줍니다. 모든 세션이 한가해지고 2분이 지나면 사라집니다. 설정 › 알림 › Live Activity에서 끌 수 있습니다. 홈 화면에는 “Foreman 현황”과 “당신 차례” 위젯을 둘 수 있습니다.

Apple Watch

Watch에서 승인 요청을 받고 거부나 허용을 누릅니다. 되돌릴 수 있는 요청은 두 번 탭 제스처로도 허용합니다. 위험한 요청은 “손목에서 허용할 수 없어요 · iPhone에서 Face ID”로 표시되니 iPhone에서 처리하세요. 질문에는 선택지 버튼이나 받아쓰기로 답합니다.

질문에 답하기

에이전트가 질문하면 선택지가 버튼으로 나오고, 권장 선택지에는 “권장”이 붙습니다. 원하는 답이 없으면 직접 입력을 누르고 답을 써서 보냅니다. 알림에서는 답장으로 바로 답할 수 있습니다.

자동 허용 규칙

승인 탭 오른쪽 위의 자동 허용 규칙에서 호스트에 저장된 규칙을 봅니다. 규칙에 맞는 요청은 묻지 않고 처리되고, 규칙에 없는 요청은 지금처럼 인박스로 옵니다. 규칙의 결과는 “자동 허용” 또는 “항상 Face ID”로 표시됩니다.

Pro에서는 요청 카드 아래의 “… 는 앞으로 자동 허용”을 눌러 같은 종류의 요청을 규칙으로 만들 수 있습니다. 만든 규칙은 호스트에 저장되고 호스트가 판단합니다.

05세션

세션 탭에는 호스트별로 세션이 모여 있습니다. 세션을 누르면 상세 화면이 열리고, 길게 누르면 터미널로 보기, 명령 복사를 고를 수 있습니다.

대화, 터미널, 변경

세션 화면 위쪽에서 세 가지 보기를 오갑니다.

대화
지시와 답, 에이전트가 읽고 고친 파일, 실행한 명령이 차례로 보입니다. 아래 입력창에 다음 지시를 씁니다. 컨텍스트 사용량과 한도가 위에 표시됩니다.
터미널
호스트의 터미널 화면 그대로입니다. 입력은 그대로 PTY로 갑니다.
변경
이 세션에서 바뀐 파일과 추가·삭제 줄 수, 브랜치를 봅니다.

세션을 멈추려면 더 보기 메뉴의 중단을 누릅니다. 한 번 더 확인한 뒤 에이전트를 멈춥니다.

터미널 보기와 키 막대

터미널 아래 키 막대에 esc tab ctrl ^C ↑ ↓ / |가 있습니다. ctrl은 한 번 누르면 다음 키와 조합됩니다. 같은 세션을 호스트의 터미널과 앱이 함께 볼 수 있고, 함께 보는 중이면 위에 표시됩니다.

새 세션

  1. 세션 탭의 새 세션을 누릅니다.
  2. 호스트를 고릅니다. 꺼진 호스트는 고를 수 없습니다.
  3. 폴더에 호스트에서 작업할 경로(예: ~/Projects/app)를 넣습니다.
  4. 에이전트를 고르고 지시에 처음 맡길 일을 씁니다.
  5. 필요하면 worktree 격리와 편집 자동 허용을 정하고 시작을 누릅니다. 편집 자동 허용을 켜면 파일 수정은 묻지 않고, 그 밖의 명령은 지금처럼 승인을 받습니다.

worktree 격리

worktree 격리를 켜면(기본값) 호스트가 이 세션만을 위한 git worktree를 만들고 foreman/<세션 ID> 브랜치에서 작업합니다. 원래 작업 폴더는 건드리지 않습니다. 세션이 끝나도 worktree는 지워지지 않으니, 결과를 확인한 뒤 평소처럼 병합하거나 지우세요.

검색

세션, 명령, 호스트 이름으로 찾습니다.

iPad와 Mac에서

iPad와 Mac의 관제 그리드는 여러 세션을 한 화면에 펼칩니다. ⌘↩로 가장 오래 기다린 요청을 허용하고 ⌘⌫로 거부합니다. 위험한 요청은 단축키로 허용되지 않습니다. Mac 앱에서는 사이드바에 호스트별 세션이, 가운데에 대화가, 아래 서랍에 터미널이 보입니다.

06Pro

구독하기

설정의 Pro 둘러보기를 누르면 구독 화면이 열립니다. 월간과 연간 중에서 고르며, 가격과 결제는 App Store가 표시하고 처리합니다.

구매 복원과 해지

새 기기에서는 설정의 구매 복원을 누르면 같은 Apple 계정의 구독이 돌아옵니다. 해지는 설정의 구독 관리나 iPhone 설정 › 내 이름 › 구독에서 합니다. 해지해도 결제한 기간이 끝날 때까지 Pro를 씁니다.

여러 호스트에서 쓰기

구독은 페어링한 모든 호스트에 적용되고, 호스트 수에는 제한이 없습니다. 앱이 호스트에 연결될 때 구독 정보가 전달되며, 호스트는 이를 스스로 확인합니다. 설정의 “호스트 라이선스”에서 호스트별 상태를 봅니다.

07항상 켜 두기

호스트가 꺼지거나 잠들면 그동안 세션도 멈추고 앱에서 연결할 수 없습니다. 에이전트를 맡겨 두는 컴퓨터는 아래처럼 준비해 두세요.

Mac

  • Foreman Host 메뉴의 로그인 시 시작을 켭니다. 로그인할 때마다 호스트가 뜨고, 꺼져도 다시 뜹니다.
  • 잠자기 방지 (세션 실행 중)는 기본으로 켜져 있습니다. 세션이 하나라도 도는 동안 Mac이 잠들지 않고, 세션이 없으면 평소처럼 잠듭니다. Foreman Host가 실행 중일 때만 작동합니다.
  • Foreman Host 메뉴의 종료는 메뉴 막대 앱만 끝냅니다. 호스트와 세션은 계속 돕니다.

Windows

foreman doctor가 아래 항목을 점검하고, 고칠 방법을 그 자리에서 알려 줍니다.

절전
전원에 연결된 동안 절전·최대 절전이 꺼져 있어야 세션이 멈추지 않습니다. 설정 › 시스템 › 전원 및 배터리 › 화면, 절전 및 최대 절전 시간 제한에서 “전원에 연결된 경우” 절전을 “안 함”으로 둡니다.
BitLocker
TPM만으로 잠금을 푸는 설정이면 다시 시작한 뒤 저절로 돌아옵니다. 시작 PIN이나 USB 키를 쓰면 누군가 잠금을 풀 때까지 호스트가 꺼진 상태로 남습니다.
다시 시작 후 로그인
호스트는 로그온해야 시작됩니다. 업데이트 뒤 자동으로 로그인되게 하려면 로그인 옵션의 “업데이트 후 내 로그인 정보를 사용하여 자동으로 설정 완료”를 켭니다.
Windows 업데이트
사용 시간을 설정해 두면 그 시간에는 업데이트로 다시 시작하지 않습니다(최대 18시간). 다시 시작하면 그때 돌던 세션은 끝납니다.

foreman doctor

foreman doctor

점검마다 한 줄씩 결과(ok, info, warn, FAIL)가 나오고, 고칠 것이 있으면 그 아래 →로 방법이 붙습니다. 호스트 데몬 실행 여부, 로그온 시 시작, 셸 연동도 함께 확인합니다. warn만 있으면 Foreman은 동작하지만 아무도 없을 때 호스트가 꺼질 수 있다는 뜻입니다.

08개인정보와 보안

우리 서버 0대

Foreman에는 개발자가 운영하는 중계·계정·로그 서버가 없습니다. 세션 내용은 내 호스트와 내 기기 사이에서만 오가고, 개발자는 아무것도 저장하거나 열람하지 않습니다. 자세한 내용은 개인정보 처리방침에 있습니다.

종단간 암호화

모든 연결은 Noise XX(X25519 · ChaCha20-Poly1305)로 처음부터 끝까지 암호화됩니다. 페어링할 때 호스트 키가 기기에 고정되므로, 다른 키를 내미는 상대에게는 연결하지 않습니다.

09자주 묻는 질문

터미널 창을 닫으면 세션도 끝나나요?

아니요. 세션은 호스트가 소유합니다. Foreman으로 시작한 세션은 터미널을 닫거나 Ctrl+]로 떼어 내도 계속 돌고, foreman attach <id>나 앱으로 다시 붙습니다.

호스트를 다시 시작하면 어떻게 되나요?

호스트 데몬만 다시 시작한 경우에는 세션이 그대로 이어지고 앱도 저절로 다시 연결됩니다. 컴퓨터를 다시 시작하면 그때 돌던 세션은 끝납니다.

터미널에서 실행한 에이전트가 앱에 안 보여요.

셸 연동이 켜져 있는지 foreman shim status로 확인하고, 연동을 설치한 뒤 새로 연 터미널에서 실행했는지 확인하세요(터미널에서 평소처럼 실행하기). Free에서는 세 번째 종류의 에이전트가 일반 터미널 세션으로 들어옵니다.

위험한 요청을 알림에서 허용할 수 없어요.

의도된 동작입니다. 되돌릴 수 없는 작업은 앱 안에서 Face ID로만 허용합니다(Face ID로 허용).

휴대폰을 잃어버렸어요.

호스트의 기기 관리(Windows는 foreman devices revoke <id>)에서 그 기기를 폐기하세요. 바로 연결이 끊기고 다시 연결할 수 없습니다(기기 관리와 폐기).

페어링할 때 숫자가 달라요.

양쪽에서 달라요를 누르고 끝내세요. 네트워크를 확인한 뒤 새 코드로 다시 시작합니다.

다른 문제가 있어요.

지원 페이지의 GitHub Issues로 알려 주세요. 기기와 OS 버전, 그리고 foreman doctor 결과를 함께 보내 주시면 빨리 확인할 수 있습니다. API 키나 토큰은 적지 마세요.

10CLI 참고

호스트에는 foreman 명령이 함께 설치됩니다. Windows에서는 PowerShell에서 바로 foreman으로, Mac에서는 /Applications/ForemanHost.app/Contents/MacOS/foreman로 실행합니다. 대부분의 명령은 --json을 붙이면 기계가 읽을 수 있는 형식으로 답합니다.

세션

명령하는 일
foreman run <에이전트> [인자…]세션을 만들고 지금 터미널에 붙입니다. 호스트 데몬이 꺼져 있으면 먼저 띄웁니다. Ctrl+]로 떼어 내도 세션은 계속 돕니다.
foreman attach <id>세션에 다시 붙습니다. id는 앞부분만 써도 됩니다.
foreman ls세션 목록(ID, 에이전트, 상태, PID, 크기, 시작 후 시간, 폴더)을 봅니다.
foreman kill <id>세션의 프로그램을 끝냅니다.

페어링과 기기

명령하는 일
foreman pair터미널에 페어링 QR 코드와 링크를 띄우고, 기기의 여섯 자리 숫자를 확인받습니다.
foreman devices페어링된 기기(ID, 이름, 플랫폼, 키, 페어링한 날, 마지막 연결, 상태)를 봅니다.
foreman devices revoke <id>기기를 폐기합니다. 열린 연결도 끊깁니다.

셸 연동

명령하는 일
foreman shim install [에이전트…]zsh 또는 PowerShell에 연동을 설치합니다. 기본 대상은 claude, codex, gemini, opencode입니다.
foreman shim status설치 상태를 봅니다.
foreman shim uninstall연동을 지웁니다.

로그온 시 시작

명령하는 일
foreman autostart status로그온 시 시작이 켜져 있는지와 방식을 봅니다.
foreman autostart enable · disable패키지 없이 설치한 Windows 호스트에서 켜고 끕니다. Mac에서는 Foreman Host 메뉴의 로그인 시 시작을 씁니다.

상태와 점검

명령하는 일
foreman status호스트 데몬의 버전, 호스트 이름, 연결 주소, 호스트 키를 봅니다.
foreman start호스트 데몬을 띄웁니다.
foreman doctor호스트가 계속 켜져 있을 준비가 됐는지 점검합니다(foreman doctor).
